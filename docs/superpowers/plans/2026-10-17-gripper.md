# Gripper Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GrabCAD two-finger gripper is added and mounted on the flange in Build. In Program mode under MuJoCo it holds objects by force-limited fingers and friction only.

**Architecture:**
- Build: the frontend gains per-file `source` on bodies, a rigid mount transform, and a `gripper` entry in the model (leader and follower finger joints, TCP offset).
- Export: writes the gripper into the URDF itself. The follower gets `<mimic>`, both finger axes point inward, and a fixed `tcp` link is added. The gripper links get CoACD convex collision pieces.
- Downstream, `parse_chain` recognises the gripper structurally (two prismatic leaves on one link, one mimicking the other), so every consumer sees it through the URDF with no extra file.
- ros2_control runs a parallel-gripper controller beside `arm_controller`. `robot.py` drives it directly for `grip` / `release`.

**Tech Stack:** as part C (ROS 2 Jazzy, MoveIt 2, ros2_control, `mujoco_ros2_control`, MuJoCo 3.x). New: `ros-jazzy-parallel-gripper-controller` and pip `coacd`. Frontend React + vitest; backend FastAPI + pytest.

**Spec:** `docs/superpowers/specs/2026-10-17-gripper-design.md`

**Deviation from the spec (ruling):** the spec's `<robot>/config/gripper.yaml` is replaced by facts carried in the URDF:
- `<mimic>`, finger limits and effort (grip force)
- the `tcp` link

The reason: the URDF already reaches every consumer, including `solver.py` inside the container, and a second file would need plumbing to each. The cost if wrong is low, because nothing outside this repo reads `gripper.yaml`.

## Global Constraints

- Two-finger parallel grippers only. The second finger mirrors the first.
- Default grip force: 40 N per finger when the finger joint has no Max torque.
- Default friction on the finger and base geoms: 1.0.
- Slip: the held object drifts more than 0.01 m relative to the TCP.
- Mount turn steps: 15°.
- No runtime glue fallback for a robot with a gripper.
- Robots without a gripper must export, parse and run exactly as on `master`.
- Exact message texts, `{…}` filled in:
  - "The fingers are one part; the gripper needs separate finger parts. Pick a different model or split it in your CAD tool."
  - "The fingers don't slide along the same line."
  - "Pick a flat face (the gripper's mounting plate and the flange)."
  - "The gripper closed on nothing: no object between the fingers at {xyz}."
  - "'{name}' slipped out of the gripper while moving ({mass:g} kg, grip force {force:g} N per finger)."
  - "'{name}' is {w:.2f} m wide; the gripper opens to {open:.2f} m."
- Backend tests: `OPENBLAS_NUM_THREADS=1 ~/miniforge3/envs/cad-to-urdf/python.exe -m pytest -q` from `backend/`.
  - Ad-hoc scripts in a worktree need `PYTHONPATH=.`.
  - Copy `corpus/irb1300_asm.stp` into the worktree for the irb1300 tests.
- Frontend: run `npm ci` once in the worktree, then `npx vitest run`.
- Container checks: irb1300 in the foreground (~5 min). Say the duration first. Never run several robots at once (low memory).

## Review Focus

1. **The same file imported twice** (for example, re-importing the gripper after deleting it) gets two distinct `source` values, so mounting one doesn't move the other. Task 4.
2. **A project saved before this feature** (no `source`, no `gripper`) loads and exports unchanged, with no gripper. Task 4.
3. **Undo after other edits:** mount, rename a link, then undo the mount. The geometry returns exactly, within 1e-9. Task 4.
4. **Deleting a finger joint** (or one of its links) that the gripper refers to clears `gripper`, so no dangling ids reach export. Task 5.
5. **Robots without a gripper:** the generated URDF, chain, brief and `robot.py` behaviour are identical to `master` (glue `attach` under physics). Tasks 7 and 9.

### Task 3: Mount maths (frontend)

**Files:** Create `frontend/src/model/mount.ts`. Test: `frontend/src/model/mount.test.ts`.

**Produces:**
- `type Mat4 = number[]` (16 numbers, row-major)
- `mountMatrix(moving: Face, target: Face, turnDeg: number, flip: boolean): Mat4`, for plane faces only. It throws `Error("Pick a flat face (the gripper's mounting plate and the flange).")` otherwise.
- `transformBody(b: Body, M: Mat4): Body`. It transforms vertices and face centres as points, and normals and axes as directions.
- `invert(M: Mat4): Mat4`

The rule: move `moving.center` onto `target.center`, and rotate so `moving.normal` = −`target.normal`. Then rotate by `turnDeg` about `target.normal` through `target.center`. With `flip`, add a further 180° about an in-plane axis through the centre.

- [ ] **Step 1:** Tests:
  - `face_meets_face`: unit cube A's +z face mounted on cube B's +x face. A's face centre ends at B's face centre, and A's face normal equals −B's normal.
  - `turn_rotates_about_the_target_normal`: turn 90°, and a vertex off-axis moves 90° about the normal.
  - `flip_reverses_the_in_plane_axis`.
  - `non_plane_face_is_refused`, with the exact message.
  - `invert_round_trips_within_1e-9`.
- [ ] **Step 2:** Run (`npx vitest run src/model/mount.test.ts`); expect FAIL. Implement. Run; expect PASS. Commit: `feat: mount transform for placing a part face-to-face`.

### Task 6: Export: mimic, inward axes, TCP, convex collision, MJCF fingers

**Files:**

**Produces** (in `gripper.py`):
- `inward_axes(leader_axis, follower_axis, leader_centroid, follower_centroid) -> (leader_axis, follower_axis, leader_flip: bool, follower_flip: bool)`. Each axis points toward the other finger. A flipped joint's limits become `(-upper, -lower)`.
- `tcp_point(base_vertices, finger_a_vertices, finger_b_vertices, offset_m) -> (xyz, approach_axis)`. The approach axis runs from the base centroid toward the fingers' midpoint. The TCP is that midpoint pushed out to the fingers' farthest extent along the axis, plus the offset.
- `convex_pieces(vertices, triangles, max_pieces=8) -> list[tuple[vertices, triangles]]`, using CoACD.

**URDF (gripper only):**
- the follower joint gets `<mimic joint="{leader}" multiplier="1" offset="0"/>`
- both finger joints get the inward axes and adjusted limits
- `<limit effort>` is the grip force (max_effort or 40)
- a `tcp` link plus a fixed joint `tcp_joint` from the gripper base link, at `tcp_point`, with z along the approach axis
- the gripper links (base and fingers) get one `<collision>` per convex piece (meshes `{link}_c{i}.stl`), while visual stays the full mesh

**MJCF:**
- the follower gets no actuator
- if Task 1 found that the URDF import doesn't create the mimic equality, add `<equality><joint joint1="{follower}" joint2="{leader}" polycoef="0 1 0 0 0"/></equality>`
- the finger and base geoms get `friction="1 0.005 0.0001"`
- the finger joints are left out of `required_efforts` and `suggest`, and their effort is the grip force
